## 风险与应对

| 风险 | 影响 | 应对方式 |
| --- | --- | --- |
| 类别严重不均衡 | Accuracy 虚高、小类召回低 | 分层划分、Macro-F1 选模、class weight 或训练集重采样 |
| 重复文本跨集合 | 指标泄漏 | 划分前按评论去重或分组划分，生成泄漏检查报告 |
| BERT 训练时间不足 | 无法及时调参 | 先完成可靠基线；使用小样本冒烟测试；保存最优验证集模型 |
| 开发周期只有约一天半 | 后期集成和答辩时间被压缩 | M2 后并行开发；9 月 22 日 10:00 开始集成验收，11:30 冻结 |
| 数据许可证不清晰 | 原始数据不宜公开分发 | Git 忽略原始数据，仅提交下载脚本和来源说明 |
| 网络或 API 不稳定 | 答辩演示失败 | 准备本地模型、截图与预录演示，不依赖现场外部 API |
| 三人修改同一文件 | Git 冲突 | 按责任模块分支开发，合并前同步并由非作者复核 |

## 状态定义

- 未开始：尚未产生代码或交付物。
- 进行中：已有改动，但未达到验收标准。
- 待验收：负责人完成并提供验证结果，等待团队复核。
- 已完成：验收标准全部满足并记录实际证据。
- 阻塞：存在明确外部依赖或需要团队决策。
